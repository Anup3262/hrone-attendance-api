| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Grace logic is wrong: `minutes if minutes > 10 else 0` returns minutes-since-start only when floor-minutes > 10. R2 says late iff punch is *strictly more than* 10:00 after shift_start, and then late_minutes = floor minutes since shift_start. | Punch 09:40:01 with shift 09:30 → starter returns 0, correct is 10. Punch 09:40:59 → starter returns 10, correct is 10 (passes by luck); punch 09:40:00.9 (truncated to 09:40:00) → starter may return 10, correct is 0. | Truncate instant to whole seconds first, convert to IST, then: if (punch_in - shift_start) > 10 minutes → floor(total_seconds/60), else 0. |
| 2 | `compute_late_minutes` | No truncation to whole seconds (R1) and no IST conversion; uses naive `replace(hour=...)` on a UTC/naive datetime. | Punch at 09:40:00.900 IST → counts as 09:40:00.900, can flip the grace boundary. Server in another TZ shifts the date. | Truncate microseconds to 0 before storing; attach UTC then convert to IST for all calendar math. |
| 3 | `compute_overtime` | Missing the 30-minute minimum: returns any positive minutes. R3 counts only when >= 30. | Sample doc 1: punch_out 18:35, shift_end 18:30 → starter returns 5, correct is 0. | `floor(minutes) if floor(minutes) >= 30 else 0`, on truncated instants. |
| 4 | `compute_overtime` | Overnight shifts broken: builds shift end with `datetime.fromisoformat(date_str).replace(hour, minute, tzinfo=IST)` — always on the attendance date, never the next day. | Shift 22:00–06:00, punch_out 06:40 next day → starter computes a large negative or wrong value. | If shift_end <= shift_start, add one day to the end datetime before diffing. |
| 5 | `compute_work_hours` | Uses Python `round()` (banker's rounding). R4 requires half-up to 2 decimals. | 2.345 hours → `round` gives 2.34 or 2.35 depending on float repr; half-up must give 2.35. | Use `Decimal` with `ROUND_HALF_UP` on seconds/3600, quantize to 0.01. |
| 6 | `punch_in` — epoch millis | `datetime.fromtimestamp(ms/1000)` yields naive local time; R1 truncation and IST date missing; response returns datetimes, not epoch millis. | Contract tests expect integers; any client gets datetimes and fails schema validation. | Parse ms → aware UTC datetime, truncate to seconds, convert to IST for `date` (with overnight rule), store BSON date, return ms ints. |
| 7 | `punch_in` — unknown employee | `emp["shift_start"]` with no 404 when `find_one` returns None → `TypeError` → 500. Contract says 404. | POST punch-in with fresh emp_code → 500 instead of 404. | Check `if not emp: raise 404` before use. |
| 8 | `punch_in` — status accepted | Accepts any string; contract allows only PRESENT/WFH/ON_DUTY here (422 otherwise). | POST with `status: "ABSENT"` → 201, should be 422. | Validate against PresenceStatus enum. |
| 9 | `punch_in` — attendance date (R1) | `d = ts.date().isoformat()` uses server-local date; ignores overnight rule (punch before shift_end belongs to previous day). | Night shift punch-in at 00:30 IST → wrong `date`, then duplicate-key or 404 confusion. | Compute IST date from truncated punch_in; if overnight and IST time < shift_end → date minus one day. |
| 10 | `punch_in` — race | Check-then-insert (`find_one` then `insert_one`); two simultaneous punch-ins both pass the check → duplicate records, one should get 409. | Parallel POSTs for same (emp_code, date) → two 201s. | Unique index on (emp_code, date); catch `DuplicateKeyError` → 409. Do not rely on the pre-check. |

| 12 | `create_employee` — race | Same check-then-insert on `emp_code`; concurrent creates → duplicates. Contract demands DB unique index, exactly one 201. | Parallel POST /employees same emp_code → two 201s. | Unique index on emp_code; catch DuplicateKeyError → 409. |
| 13 | `create_employee` — validation missing | No checks: emp_code pattern `^EMP\d{4,6}$`, email format, `shift_start != shift_end` (422), `joined_on` date shape. | `emp_code: "abc"`, `shift_start == shift_end` → 201, should be 422. | Pydantic patterns + explicit shift equality check. |
| 14 | `create_employee` — `created_at` | `datetime.now()` naive local; contract wants server-set instant returned as epoch millis. | Returned `created_at` is a datetime string, not millis; TZ ambiguous. | `datetime.now(timezone.utc)` truncated to seconds; return millis. |
| 15 | `list_employees` — pagination | `skip = page * page_size` (off by one page); `total = count_documents({})` ignores the department filter; no sort by emp_code; no page/page_size bounds (max 100). | Page 1 skips the first 20 rows; filtered total is wrong. | `skip=(page-1)*page_size`, `count_documents(q)`, `.sort("emp_code",1)`, validate 1<=page, 1<=page_size<=100. |
